## 这是什么

稻盛和夫的哲学不是一个「提示词」。它是一个**决策操作系统**。

**四个子系统：**

| 子系统 | 做什么 | 例子 |
|---|---|---|
| 输入分类器 | 12 种问题类型，关键词和情绪匹配 | 「我很焦虑」→ 自动路由到肺结核故事 |
| 路由器 | 映射到稻盛人生中对应的阶段和故事 | 焦虑 → 13 岁肺结核领悟「心中磁石」 |
| 响应构建器 | 哲学条目 + 具体执行动作 | 「哲学：心像庭院 → 执行动作：写下今天的负面念头，问自己——这对我有帮助吗？没有就划掉。」 |
| 比喻数据库 | 10 个比喻（竹子、水库、土俵、花园……） | 「低谷是竹子在长节。节是在大风大雨时长出来的。」 |

**876 行 SKILL.md，20 条哲学条目，12 种问题类型，10 个人生阶段，10 个比喻，8 种语气。**

## 安装与使用

### 方式一：复制粘贴（30 秒，零技术门槛）

适合 ChatGPT、Claude、Gemini 等任何大模型。

1. 打开 [`prompts/system-prompt.md`](prompts/system-prompt.md)
2. 复制全部内容
3. 粘贴到 AI 的系统提示词 / 自定义指令中
4. 开始对话，AI 会以稻盛和夫的身份回应你

> **即用链接：** [完整版](prompts/system-prompt.md) | [精简版（约 1 页）](prompts/system-prompt-mini.md)

### 方式二：Claude Code Skill（1 分钟）

```bash
git clone https://github.com/ImnotKrisWu/inamori-skill.git
cp -r inamori-skill/skill ~/.claude/skills/inamori/
```

在 Claude Code 中输入 `/inamori` 即可唤起稻盛和夫。

### 方式三：MCP Server（5 分钟，所有 AI 客户端通用）

适用于 Claude Desktop、Cursor、Continue、Copilot 等任何支持 MCP 的客户端。

```bash
git clone https://github.com/ImnotKrisWu/inamori-skill.git
cd inamori-skill/mcp-server
pip install mcp
```

在 MCP 客户端配置中添加：

```json
{
  "mcpServers": {
    "inamori": {
      "command": "python3",
      "args": ["/path/to/inamori-skill/mcp-server/server.py"]
    }
  }
}
```

提供 5 个工具：

| 工具 | 用途 |
|---|---|
| `inamori_consult` | 主入口：向稻盛和夫咨询任何问题 |
| `inamori_classify` | 仅分类问题类型，返回推荐哲学 |
| `inamori_metaphor` | 查询比喻库 |
| `inamori_read_file` | 读取本地数据文件（安全目录白名单） |
| `inamori_generate_artifact` | 生成表格/方案模板（预算表、决策矩阵等） |

> [MCP Server 详细文档](mcp-server/README.md)

### 方式四：命令行（即时）

```bash
./cli/inamori --metaphor "竹子"
./cli/inamori --classify "失败"
./cli/inamori --list
```

## 系统架构

```
用户输入
    │
    ▼
┌──────────────┐
│  问题分类器   │  12 种类型：内心不安、逆境打击、濒临放弃、经营问题、
│              │  选择判断、成功自满、领导问题、人生意义、
│              │  关系家庭、工作倦怠、财务经营、组织变革
└──────┬───────┘
       │
       ▼
┌──────────────┐
│   路由器     │  映射到 10 个人生阶段（1932-2022）
│              │  童年战火 → 少年卖纸袋 → 求职绝望 → 松风实验室 →
│              │  京瓷创业 → KDDI → 癌症出家 → 拯救日航 → 最后岁月
└──────┬───────┘
       │
       ▼
┌──────────────┐
│  交互模式    │  追问模式 / 空巴模式 / 数字模式 / 讲故事模式
│              │  根据用户状态自动切换
└──────┬───────┘
       │
       ▼
┌──────────────┐
│  响应构建器   │  哲学条目 + 具体执行动作 + 比喻
│              │  格式：哲学：xxx → 执行动作：xxx
└──────┬───────┘
       │
       ▼
┌──────────────┐
│  记忆锚点    │  写入长期记忆（数字锚点、情绪锚点、决策锚点）
│              │  下次对话主动追问
└──────────────┘
```

### 核心能力

**四种交互模式：**
- **追问模式** — 用户说得模糊时，不猜，先追问「具体数字是多少？」「什么时候开始的？」
- **空巴模式** — 用户情绪低落时，切换到放松的对话风格，先共情再说理
- **数字模式** — 提到经营/财务时，像日航查账一样追问每一个数字
- **讲故事模式** — 用户需要启发时，展开完整故事（时间、地点、细节、转折点）

**长期记忆与跨周期追踪：**
- 对话结束自动写入记忆锚点
- 下次对话主动发问——「上次提到的现金流缺口，补上了吗？」

**领域边界与熔断机制：**
- 三级熔断：温和拉回 → 直接戳穿 → 沉默拒绝
- 拒绝闲聊、纯技术命令，把执行问题降维到决策问题

**执行动作自动化：**
- 6 种模板：三年亏损预算、现金流追踪、决策矩阵、行动计划、每日反省、阿米巴核算表

## 设计理念

**SKILL.md 是唯一真相来源。** System Prompt、MCP 的结构化数据、CLI 工具、文档——全部从 SKILL.md 派生。

**MCP Server 不调用 LLM。** 它是纯「数据 + 分类」服务器。调用方 AI 负责生成回应。零 API 费用，零外部依赖，零延迟。

**铁律：哲学条目必须附带具体执行动作。** 不能说「要利他」就结束——必须说清楚具体怎么做。格式：`哲学：xxx → 执行动作：xxx`。
